The data bottleneck

Real work needs data that reflects real work.

Productivity tasks ask an agent to follow a long-horizon professional workflow, read heterogeneous files and hand back a usable deliverable. Existing training data covers these skills one at a time. The paper argues that what is missing is not more data but data that reflects real work: real intents, authentic files, and deliverable-level standards.

Usual sourceAgent-R² source
Workflow manually authored workflows, which do not scale blueprints mined from a web corpus with occupational activity seeds (O*NET)
Files LLM-generated files without real layouts, gaps or cross-file references public files found on the web, verified, and kept in their original format
Success “an output file exists” fine-grained rubrics over evidence, analysis and deliverable quality

Method

From an occupational seed to a trained agent

Three synthesis stages turn a web-corpus segment into a task with real attachments and a rubric; an expert solves it to produce reference files and a trajectory; the rubric is checked and refined. The model is then trained with SFT and rubric-based RL.

Setup

Task, environment and training recipe

Task

A task is x = (I, Fa, Fr, R): instruction, attachments available while solving, reference files used only for evaluation, and a task-specific rubric. The agent must produce the deliverable files Fd that I asks for.

Environment

A persistent sandbox with four general tools: bash, web_search, web_fetch, view_image. Text-only solvers answer view_image through an auxiliary vision model (Qwen3-VL-4B-Thinking for Agent-R² variants).

Recipe

3k tasks for SFT and 1k disjoint tasks for RL. GRPO with batch size 16, group size 4, up to 40 assistant turns, 65,536 max response length, temperature 1.0, learning rate 1×10−6. Final checkpoints, no benchmark-based selection.

Analysis

Fewer shortcuts, longer grounded exploration

Shortcut behavior: the agent writes a plausible-looking deliverable before it has grounded, built or verified it. The base model makes few tool calls and stops early; SFT teaches sustained exploration; rubric-based RL turns that into reliable completion.

Takeaways

  1. Ground every stage in real sources. Workflows come from web-corpus evidence and occupational seeds, files from the web, and rubrics from the verified workflow-file context.
  2. Real files matter. Matched tasks with real attachments train a better SFT model than synthetic files (43.3 vs 41.4) and demand 2.54× more expert tool calls.
  3. Rubrics make RL count. Scoring rendered deliverables against fine-grained rubrics lifts Agent-R²-4B from 45.3 (SFT) to 51.0 on GDPval and reduces shortcut behavior.

Quick start

Run the pipeline

Fill URLs, keys and the proxy once in Agent-R2/settings/settings.yaml; every module reads it. See the README for data placeholders and the sandbox.

1 · Synthesize data

cd Agent-R2/data_sythesis
python run.py   # scenario → search → question → solver → refine
python prepare_sft_data_split.py   # → data/sft.jsonl
python prepare_rl_data.py          # → rl_data/data{N}.zip

2 · SFT (ms-swift)

cd ms-swift
MODEL_PATH=/path/to/Qwen3-4B-Thinking-2507 bash run_qwen3.sh

3 · Rubric-based RL (verl)

cd verl
python recipe/agent_r2/preprocess.py
MODEL_PATH=/path/to/sft_checkpoint bash recipe/agent_r2/run_agent_r2.sh

4 · Evaluate

cd Agent-R2
python gdpval/run.py
python officeqa/run.py
